F1 ROOT CAUSE (differs from the original brief)
------------------------------------------------------------
The prescribed fix -- RichHandler(show_time=False, show_path=False)
-- was ALREADY present in the code and already committed
(Stage C3.9.2 / v48.0.2). It was never the cause.

The offending line was produced by a different emitter:

    _RichProgress.note()  ->  Console.log(message)

rich's Console.log() renders through LogRender, whose Console
defaults are show_time=True and show_path=True. Those flags are
per-Console and are NOT inherited from the logging RichHandler
built in _setup_logging(). So the auth summary carried a
timestamp, the source file and an OSC-8 hyperlink.

Reproduced before the fix (profile quick, console path):

  [05:16:23] [WARNING] 3 enabled provider(s) missing API keys:
      reconip.py:16344        <- OSC-8 hyperlink to the source line

Fixed by using Console.print(), which emits the message verbatim.
It still lands above the live progress region, because rich's Live
redirects sys.stdout/stderr through a FileProxy (verified with an
isolated Live/print/log harness under a pty).

console.print() is present in every rich release; verified against
both rich 15.0.0 (host) and rich 13.9.4 (pinned in requirements.txt).
